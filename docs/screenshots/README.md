# Screenshots

Empty until the demo is deployed. The point of a screenshot is to show the
product as a visitor meets it, so the set is captured against the live URL rather
than from a local run standing in for one.

The shot list — ten frames, each with the exact state to capture and the reason
that frame carries the point — is in
[`../demo-runbook.md`](../demo-runbook.md). Files land here with these names:

```
01-landing.png              06-dashboard-search.png
02-room-two-peers.png       07-export.png
03-screen-share.png         08-turn-badge.png
04-chat.png                 09-ci-summary.png
05-summary-action-items.png 10-lighthouse.png
```

Anything that a still frame cannot carry (a tick propagating to the other
participant, a mute labelling a peer's tile, a screen share replacing the camera)
belongs in the demo video, which the same runbook scripts beat by beat.
